# MicroChat для iPhone — версия 0.5

Нативное приложение SwiftUI собрано облачным Xcode для настоящего iPhone (arm64).
Получен **неподписанный IPA**. Для установки нужна подпись Apple и подходящий
профиль; сам по себе неподписанный файл не устанавливается на iPhone.
Apple Developer аккаунт, сертификат и профиль установки в проект не включены.

Требования приложения: **iOS 17 или новее**, iPhone. Проект использует штатные
SwiftUI, CryptoKit, Keychain и URLSession. На Mac не нужны CocoaPods, Firebase SDK
или отдельные файлы конфигурации пользователя.

## Как устроена переписка

Android 0.4 и iOS 0.5 используют уже настроенный общий Firebase
`microchat-msg-b66294`. Публичная конфигурация упакована в приложение;
административных ключей и OAuth-токенов Google в проекте iOS нет.
Сервер и его правила при подготовке iOS не изменялись.

После установки пользователь задаёт имя, открывает «Моё приглашение» и отправляет
его собеседнику. Оба участника добавляют приглашения друг друга через «Новый чат».
Это разрешает доставку в обе стороны. Можно общаться между Android и iPhone.
«Избранное» хранит заметки только на конкретном устройстве.

Интерфейс сохраняет выбранное оформление Velvet: бордовый фон, коралловые акценты,
заголовок «Чаты», поиск и кнопки с подписями. Есть контакты, приглашения, профиль,
черновики, счётчики непрочитанного, локальная история и очередь повторной отправки.
Новых демонстрационных собеседников приложение не создаёт.

В текущей версии приём работает, пока приложение открыто. Нет фоновых уведомлений,
звонков, вложений, сетевых групп, восстановления аккаунта и синхронизации устройств.
Кнопка «Звонки» сообщает, что функция ещё не реализована. **REALITY в iOS-клиент
не встроен**: он использует HTTPS со сквозным шифрованием. Отдельный REALITY-сервер
для Android тоже пока не настроен.

## Проверки и границы результата

`Core/` содержит настоящий Swift-код протокола. При проверке в Linux он использует
официальный Swift Crypto; на iPhone и Mac тот же код использует CryptoKit.
Проверяются расшифрование конверта из Android SecureCrypto/Tink, экспорт ключей,
формирование ответа для Android, подмена полей, неверные ключи и ограничения текста.
Тестовые ключи в `Tests/Fixtures/android-v1.json` публичные и не относятся к аккаунтам.

Подробный результат проверки находится в `VALIDATION_RU.md`. В облачном Xcode
прошли 9 тестов протокола на Mac, сборка приложения для iPhone и 12 тестов
в iOS Simulator, включая Keychain и шифрованное хранилище. Проверка в симуляторе
не заменяет тестирование на физических телефонах. Сквозная
переписка двух установленных приложений на Android и iPhone ещё не проверена.

## Установка на iPhone без собственного Mac

Программировать или собирать проект владельцу телефона не требуется: IPA уже
создан в облаке. Неподписанный IPA сначала нужно подписать для конкретного
владельца или выбранного канала распространения.

Бесплатный вариант для личной проверки — **AltStore Classic на Windows**:

1. На компьютере Windows установить AltServer и необходимые iTunes/iCloud
   по [официальной инструкции AltStore](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows).
2. Подключить iPhone по USB, подтвердить доверие и установить AltStore Classic
   через AltServer. Владелец входит в свой Apple Account непосредственно
   в программе установки; пароли в чат и в репозиторий не передаются.
3. На iPhone подтвердить доверие профилю и включить Developer Mode, если
   это потребуется по инструкции. Сохранить IPA в «Файлы», открыть AltStore
   → My Apps → «+» и выбрать файл MicroChat.
4. Обновлять подпись через AltStore до истечения **7 дней**. Для обновления
   AltStore должен иметь соединение с AltServer. Это ограничение бесплатной
   установки описано в [официальном руководстве](https://faq.altstore.io/altstore-classic/your-altstore).

Подключение реального iPhone к компьютеру и вход владельца в Apple Account
не выполняются облачной сборкой. Работа MicroChat после такой установки
ещё должна быть проверена на физическом телефоне.

Другой вариант — TestFlight через аккаунт Apple Developer Program с подготовкой
подписанной сборки. Членство обычно стоит 99 USD в год, цена зависит от региона:
[условия Apple](https://developer.apple.com/programs/enroll/). Платные сервисы
и членство при текущей сборке не подключались.

## Открыть и запустить на Mac

1. Установить Xcode с SDK iOS 17 или новее, совместимый с версией iOS телефона.
2. Открыть `MicroChat.xcodeproj`; выбрать схему **MicroChat**.
3. Для симулятора выбрать доступный iPhone Simulator и нажать Run.
4. Для телефона открыть Signing & Capabilities и выбрать свой Team в Xcode.
   Если идентификатор занят, изменить Bundle Identifier приложения и тестов.
   Это не меняет общий сервер и совместимость переписки.
5. Подключить iPhone, выполнить требования Xcode к доверию/Developer Mode и нажать Run.

Бесплатный аккаунт Apple позволяет тестировать приложение на собственном устройстве
через Xcode. Для выбранного способа распространения другим пользователям могут
потребоваться членство Apple Developer Program, сертификат и provisioning profile.
Не покупай подписку до выбора способа установки.

## Сборка из терминала macOS

Свой iPhone для написания и сборки кода не требуется. Mac также может быть
облачным: сценарий GitHub Actions опубликован в
`.github/workflows/microchat-ios.yml` отдельной ветки `codex/microchat-ios` и уже
создал IPA. Копия сценария находится в `ci/microchat-ios.yml`.
Он проверяет ядро на Mac, создаёт **неподписанный** IPA и запускает тесты
в iOS Simulator. Сам по себе такой IPA не устанавливается на телефон; подпись
остаётся отдельным обязательным шагом. Сценарий не получает ключи подписи Android.
Исходные файлы игр и основная ветка репозитория не изменяются.

Дальнейшие команды предназначены для среды сборки, а не для обычного пользователя.

```sh
./build-ios.sh simulator
```

Сначала запускаются тесты ядра, затем собирается приложение для симулятора.
Для тестов внутри iOS Simulator:

```sh
xcrun simctl list devices available
MICROCHAT_IOS_DESTINATION='platform=iOS Simulator,id=UUID_СИМУЛЯТОРА' ./build-ios.sh test
```

`./build-ios.sh archive` создаёт только **неподписанный** Xcode Archive.
Он не является готовым файлом установки.

Чтобы получить подписанный IPA, сначала настроить подпись в Xcode и подготовить
ExportOptions.plist для выбранного способа распространения:

```sh
MICROCHAT_TEAM_ID='ТВОЙ_TEAM_ID' \
MICROCHAT_EXPORT_OPTIONS='/полный/путь/ExportOptions.plist' \
./build-ios.sh ipa
```

Результат экспорта: `build/IPA/`. Скрипт не публикует приложение и не загружает его
в App Store Connect. Для Ad Hoc в профиль должны быть включены конкретные iPhone.
Для TestFlight следует использовать Archive → Distribute App в Xcode и аккаунт
Apple Developer Program. Ключи подписи и пароли не входят в проект.

## Хранение и шифрование

HPKE X25519/HKDF-SHA256/AES-256-GCM и Ed25519 совместимы с Android-протоколом v1.
Ключи контакта закрепляются из приглашения и сверяются с неизменяемым профилем.
Сообщение сохраняется в зашифрованное локальное хранилище до удаления из очереди.
Повторная отправка использует тот же ID и конверт; история устраняет дубли.

Состояние, приватные ключи и токены зашифрованы AES-GCM. Мастер-ключ защищён
Keychain с `WhenUnlockedThisDeviceOnly`; файл использует Complete File Protection
и исключён из резервных копий. При повреждении файла или недоступности ключа
приложение блокирует работу и не создаёт новую личность поверх старой.
Невосстановимые ошибки записи тоже блокируют работу до повторного открытия.

Это экспериментальный протокол без независимого аудита, Double Ratchet и защиты
прошлой переписки при последующей утечке постоянного приватного ключа. Сервер
видит идентификаторы, время доставки и шифротекст. Метаданные TLS и Firebase
не скрываются. Приватные ключи нельзя восстановить по имени профиля.

Подробности формата: `PROTOCOL.md`.
